### D-03. 이번 프로젝트에서는 Redis와 PostgreSQL을 함께 사용했습니다. 두 기술은 각각 어떤 역할을 하며, 하나의 데이터베이스만 사용하지 않고 분리한 이유는 무엇인가요?



**모범답변** 

Redis와 PostgreSQL은 데이터를 저장하고 관리하는 목적이 다르기 때문에 함께 사용했습니다.

Redis는 동일한 이미지를 다시 분석할 때 이전 결과를 빠르게 재사용하는 캐시(Cache) 역할을 하며, 비동기식에서는 Celery Worker에 작업을 전달하는 메시지 브로커(Broker) 역할도 합니다.

반면 PostgreSQL은 비동기식 이미지 분석의 작업 상태(`queued`, `running`, `done`, `failed`)와 최종 예측 결과를 `image_jobs` 테이블에 저장하여, 작업 이력을 관리하는 역할을 합니다.

즉, Redis는 빠른 데이터 재사용과 작업 전달을 담당하고, PostgreSQL은 작업 결과와 이력을 안정적으로 저장하기 위해 사용합니다.

추가 확인 질문

1. 동일한 이미지를 다시 분석했을 때 Redis는 어떤 역할을 하나요?
    
2. 비동기식 이미지 분석에서 Celery Worker는 Redis를 어떻게 사용하나요?
    
3. 이미지 분석이 완료된 후 작업 상태와 최종 결과는 어느 데이터베이스에 저장되나요?
    
4. Redis 캐시가 만료되어도 PostgreSQL에 저장된 기존 분석 기록은 유지되나요?

### D-04. ORM과 SQL은 각각 무엇이며, 데이터베이스를 처리하는 방식에 어떤 차이가 있나요? 이번 프로젝트에서는 ORM을 어떻게 활용했나요?



**모범답변** 

SQL(Structured Query Language)은 데이터베이스에서 데이터를 조회, 추가, 수정, 삭제하기 위해 사용하는 언어입니다. 개발자가 `SELECT`, `INSERT`, `UPDATE`, `DELETE` 등의 SQL 문을 직접 작성합니다.

ORM(Object-Relational Mapping)은 SQL을 직접 작성하는 대신 Python 클래스와 객체를 이용하여 데이터베이스를 관리하는 기술입니다.

이번 프로젝트에서는 SQLAlchemy ORM을 사용하여 `ai/models.py`의 `ImageJob` 클래스를 PostgreSQL의 `image_jobs` 테이블과 연결했습니다.

|구분|SQL|ORM|
|---|---|---|
|처리 방법|SQL 문을 직접 작성|Python 클래스와 객체 사용|
|데이터 조회|`SELECT`|`db.get()` 등|
|데이터 추가|`INSERT`|`db.add()` + `db.commit()`|
|데이터 수정|`UPDATE`|객체 속성 변경 + `db.commit()`|
|장점|복잡한 쿼리를 직접 제어하기 좋음|Python 코드와 연계하여 개발·유지보수하기 편리함|

ORM도 내부적으로는 데이터베이스에 SQL을 실행합니다. 따라서 ORM은 SQL을 대체하는 별개의 데이터베이스가 아니라, SQL 작업을 Python 객체 중심으로 처리할 수 있게 해주는 기술입니다.

추가 확인 질문

1. ORM을 사용하면 SQL을 전혀 몰라도 개발할 수 있나요?
    
2. 이번 프로젝트의 `ImageJob` 클래스는 PostgreSQL의 어떤 테이블과 연결되나요?
    
3. ORM에서 `db.add()`와 `db.commit()`은 각각 어떤 역할을 하나요?
    
4. 복잡한 데이터 조회가 필요한 경우 ORM과 직접 작성한 SQL 중 어떤 방식을 선택하겠습니까?

### D-07. HTTP 200과 202는 이번 서비스에서 어떻게 다르게 사용되나요?


**모범답변** 

동기 분류는 모델의 분석 결과를 포함해 HTTP 200으로 반환합니다. 
비동기 접수는 분석을 끝내지 않은 상태에서 HTTP 202와 `job_id`를 먼저 돌려줍니다. 최종 결과는 별도의 GET 상태 조회 API로 확인합니다.

### D-08. HTTP 400·404·413·503 오류가 발생하는 대표 상황을 설명해 보세요.


**모범답변** 

400은 올바르지 않은 이미지, 413은 5MB 초과 업로드, 404는 존재하지 않는 `job_id`, 503은 Redis Broker 작업 등록 실패 상황입니다. 발생 위치에 따라 `router_sync.py` 또는 `router_async.py`와 관련 로그를 확인합니다.

**추가 확인** 오류별 입력과 해당 API를 연결하는가?

### D-09. 비동기 방식이 동기보다 HTTP 접수 응답이 빠르다면 AI 모델도 더 빨라졌다고 말할 수 있나요?


**모범답변** 

그렇지 않습니다. 비동기 API는 Worker에게 작업을 맡기고 202만 먼저 반환하므로 접수 응답이 짧아질 수 있습니다. 최종 결과 완료시간과 실제 추론시간, Redis 캐시 HIT/MISS를 분리해서 비교해야 합니다.
