### A-02 ★. 왜 `microsoft/resnet-18`을 그대로 사용하지 않고 Fine-tuning해야 하나요?

### 쉽게 말하면 Hugging Face에서 다운로드한 ResNet18 모델을 그대로 사용하면 콩잎의 질병을 분류할 수 있나요? 왜 추가 학습이 필요한가요?


**모범답변** 
Hugging Face의 `microsoft/resnet-18`은 원래 고양이, 강아지, 자동차 등 일반적인 사물을 1,000개 종류로 분류하도록 학습된 모델입니다.

따라서 이 모델을 다운로드해서 그대로 실행하면 콩잎이 정상인지, 반점병인지, 녹병인지 구분하도록 학습된 상태가 아닙니다.

우리 프로젝트에서는 콩잎 이미지를 다음 3개 클래스로 구분해야 합니다.

- `angular_leaf_spot`: 각진잎반점병
    
- `bean_rust`: 녹병
    
- `healthy`: 정상
    

그래서 기존 ResNet18이 학습한 이미지 특징을 활용하되, 마지막 분류층을 1,000개 클래스에서 3개 클래스로 변경하고 콩잎 이미지로 추가 학습합니다.

이 과정을 Fine-tuning이라고 합니다.

### A-03 ★. Hugging Face에서 콩잎 데이터셋을 다운로드한 후, 데이터를 어떻게 분류하고 관리했나요? 클래스별 이미지 개수와 데이터 누출은 어떻게 확인했나요?


**모범답변** 

Hugging Face에서 제공하는 Beans 데이터셋을 다운로드한 후, 
데이터의 용도에 따라 `train`, `val`, `test` 세 폴더로 구분했습니다.

각 폴더에는 다음 3개 클래스의 이미지를 배치했습니다.

- `angular_leaf_spot`: 각진잎반점병
    
- `bean_rust`: 녹병
    
- `healthy`: 정상
    

Train은 모델 학습, Validation은 학습 중 성능 확인과 모델 선택, Test는 최종 성능 평가에 사용합니다.

먼저 각 클래스별 이미지 개수를 확인하여 특정 클래스에 데이터가 지나치게 적거나 많은지 점검했습니다. 클래스별 수량이 불균형하면 특정 클래스에 편향된 학습 결과가 나올 수 있기 때문입니다.

또한 데이터 누출을 방지하기 위해 동일한 이미지나 같은 원본에서 생성된 중복 이미지가 Train·Validation·Test에 함께 포함되지 않았는지 확인해야 합니다.

이번 프로젝트는 이미 `train`, `validation`, `test`로 구분되어 제공된 데이터셋을 사용하므로, 임의로 데이터를 다시 섞지 않고 원본 분할을 유지했습니다. 제공된 `validation` 폴더는 학습 코드에 맞춰 `dataset/val`로 배치했습니다.

마지막으로 Test 데이터는 학습이나 모델 설정 변경에 사용하지 않고 최종 평가용으로 별도 보관했습니다.

### A-04 ★. `training/finetune.py` 파일의 `FolderImages` 클래스는 어떤 역할을 하나요? 각 이미지의 정답 라벨을 코드에서 어떻게 지정하는지 설명해 주세요.


**모범답변** 

`training/finetune.py`의 `FolderImages` 클래스는 클래스별 폴더에서 이미지를 읽고 정답 라벨을 지정하는 역할을 합니다.

`run()` 함수에서 폴더명을 알파벳순으로 정렬하고, `FolderImages`의 `__init__()`에서 `enumerate(classes)`를 이용해 숫자 라벨을 부여합니다.

- `angular_leaf_spot` → 0 (각진잎반점병)
    
- `bean_rust` → 1 (녹병)
    
- `healthy` → 2 (정상)
    

이후 `__getitem__()`에서 이미지와 정답 라벨을 학습에 사용할 수 있도록 반환합니다.

핵심: 이미지 내용을 분석해 정답을 결정하는 것이 아니라, 이미 분류된 폴더명을 기준으로 정답 라벨을 지정하는 코드입니다.

### A-05 ★. ResNet18은 콩잎 이미지가 정상인지, 반점병인지, 녹병인지 어떤 기준으로 판단하나요? 그 기준을 학습시키는 코드는 어디에 있나요?


**모범답변** 

ResNet18은 사람이 직접 정한 색상이나 병반 크기 기준으로 판단하는 것이 아니라, 콩잎 이미지와 정답 라벨을 반복 학습하면서 분류에 필요한 특징을 학습합니다.

관련 코드는 `training/finetune.py`에 있습니다.

```python
# ① 이미지와 정답 라벨로 모델 학습
result = model(**batch)

# ② 예측과 정답의 차이를 줄이도록 학습
result.loss.backward()
optim.step()
```

실제 판정코드는 어디에 있나요? `ai/services.py`에 있습니다.

```python
raw = get_classifier()(image, top_k=5)
```

### A-07 ★. ResNet18을 Fine-tuning한 후 모델의 성능을 어떻게 검증했나요? 최종 모델은 어떤 기준으로 선택했으며, Test 데이터로도 평가했나요?


**모범답변** 

`training/finetune.py`에서 Train 데이터로 모델을 학습한 뒤, 매 Epoch마다 Validation 데이터로 정확도(Accuracy)를 계산했습니다.

- Train Loss: 학습 과정에서 모델의 손실이 어떻게 변하는지 확인합니다.
    
- Validation Accuracy: 학습에 사용하지 않은 검증 이미지에서 정답을 얼마나 맞혔는지 확인합니다.
    
- 최종 모델 선택: Validation Accuracy가 가장 높았던 Epoch의 모델을 저장합니다.
    

학습 결과는 `training_report.json`에 기록되며, 가장 좋은 모델은 `artifacts/beans_resnet18/`에 저장됩니다.

현재 제공된 코드는 Train·Validation 평가까지만 자동으로 진행하며, Test Accuracy는 계산하지 않습니다. 따라서 별도로 Test 평가를 수행하지 않았다면 최종 테스트 성능은 아직 확인하지 않은 상태입니다.

### A-08 ★. 콩잎 데이터로 ResNet18을 학습한 후 검증 결과에서 어떤 문제점을 발견했나요? 그 문제를 해결하기 위해 어떤 개선 실험을 진행했으며, 개선 효과는 어떻게 확인했나요?


**모범답변** 
먼저 `training/finetune.py`에서 클래스별 Train·Validation 이미지 수량과 데이터 구성을 확인하고 ResNet18을 Fine-tuning했습니다.

학습 후 `training_report.json`에 기록된 Train Loss와 Validation Accuracy(애큐러시:정확도)를 확인하여 모델성능을 분석했습니다.

성능이 기대보다 낮거나 개선되지 않았다면 다음 사항을 점검할 수 있습니다.

1. 데이터 문제: 클래스별 이미지 수량 불균형, 잘못된 정답 라벨, 중복 이미지 여부
    
2. 학습 설정: Epoch(에포크), Learning Rate, Batch Size 등이 학습 결과에 미친 영향
    
3. 모델 학습 방식: Backbone을 고정한 Head-only 학습과 전체 Fine-tuning의 성능 차이
    
4. 이미지 특성: 조명, 배경, 병반 형태 등의 차이가 오분류에 영향을 주었는지
    

이후 발견한 문제를 바탕으로 개선 실험을 진행하고, 동일한 Validation 데이터를 사용하여 변경 전후의 Accuracy를 비교합니다.

예를 들어 Head-only 학습과 전체 Fine-tuning을 각각 수행한 뒤 결과를 비교하여 어떤 방식이 더 적합했는지 판단할 수 있습니다.

### Backbone과 Head란 무엇인가요?


ResNet18 모델은 크게 **Backbone(특징 추출 부분)**과 **Head(최종 분류 부분)**로 나눌 수 있습니다.
- Backbone: 이미지의 모양, 색상, 질감, 무늬 등 분류에 유용한 특징을 추출하는 신경망 부분입니다.
- Head: Backbone이 추출한 특징을 이용해 최종적으로 어느 클래스에 해당하는지 점수를 계산하는 부분입니다.

### Head-only 학습과 전체 Fine-tuning의 차이


Head-only 학습은 기존 ResNet18의 Backbone을 고정하고 마지막 분류층만 학습하는 방식으로, 학습 속도가 빠르고 연산 자원이 적게 필요합니다. 반면 전체 Fine-tuning은 Backbone과 분류층을 모두 학습하여 콩잎 데이터의 특징에 맞게 모델을 조정하는 방식입니다.

다만 전체 Fine-tuning이 항상 더 정확한 것은 아니며, 데이터의 양과 품질에 따라 Head-only 학습이 더 좋은 성능을 보일 수도 있으므로 두 방식의 실제 검증 결과를 비교하여 적합한 방법을 선택해야 합니다.

현재 제작한 `training/finetune.py`는 Head-only 학습과 전체 Fine-tuning을 모두 지원하도록 작성되어 있습니다.

우리가 제작한 수업자료는 Head-only를 기본 실습으로 사용하지만, 코드를 수정하지 않고 실행 옵션만 변경하여 전체 Fine-tuning도 실험할 수 있도록 설계했습니다.

### A-09 ★. 콩잎 데이터셋을 Train·Validation·Test로 나눌 때 어떤 기준을 적용했나요? 데이터 누수(Data Leakage)을 방지하기 위해 무엇을 확인했나요?


**모범답변** 

이번 프로젝트에서는 Hugging Face에서 제공하는 Beans 데이터셋의 기존 `train`, `validation`, `test` 분할을 유지하여 사용했습니다.

데이터를 분할할 때는 각 클래스의 이미지 개수와 비율을 확인하고, 동일한 이미지나 같은 잎에서 촬영한 유사 이미지가 서로 다른 데이터셋에 들어가지 않도록 하는 것이 중요합니다.

실제 산업현장에서는 촬영 날짜, 카메라, 생산 로트, 제품 ID 등 데이터의 특성에 맞는 기준으로 그룹을 나누어 데이터 누출을 방지합니다.

또한 데이터 증강을 적용한다면 Train·Validation·Test를 먼저 분리하고 Train 데이터에만 증강을 적용해야 합니다.

이번 프로젝트의 기본 학습 코드에는 자동 중복 검사가 없으므로, 실제로 중복 여부를 검사했는지는 별도로 확인해야 합니다.

### A-12 ★. ResNet18 Fine-tuning 후 Validation Accuracy가 낮거나 Train Loss가 충분히 감소하지 않는다면, Epoch·Batch Size·Learning Rate 중 어떤 설정부터 변경하겠습니까? 그 이유와 성능 개선을 검증하는 방법을 설명해 주세요.



**모범답변** 

먼저 `training/finetune.py`에서 학습한 결과를 확인하고, Train Loss와 Validation Accuracy의 변화에 따라 하이퍼파라미터를 조정하겠습니다.

- Learning Rate(학습률): Loss가 크게 흔들리거나 불안정하면 학습률을 낮춰 가중치가 더 안정적으로 업데이트되도록 합니다.
    
- Epoch(학습 반복 횟수): Loss가 계속 감소하고 Validation Accuracy도 개선되고 있다면 학습 횟수를 늘려볼 수 있습니다. 반대로 Train 성능만 좋아지고 Validation 성능이 악화되면 과적합을 의심합니다.
    
- Batch Size(배치 크기): GPU·메모리 사용량과 학습 안정성을 고려하여 조정합니다. Batch Size를 변경하면 학습 과정에도 영향을 주므로 성능을 다시 비교해야 합니다.
    

이번 프로젝트에서는 `training/finetune.py`의 `--epochs`, `--batch-size`, `--lr` 옵션으로 설정할 수 있습니다.

예를 들어 기본 학습 결과가 좋지 않다면 다른 조건은 유지하고 Learning Rate만 변경하여 재학습한 후 동일한 Validation 데이터에서 성능을 비교하겠습니다.

이때 최고 Validation Accuracy뿐 아니라 Loss 변화도 함께 확인하고, 최종 모델은 별도의 Test 데이터로 평가해야 합니다.

3. Learning Rate를 `2e-4`(2 곱하기 10의 마이너스 4승)에서 `1e-4`(1 곱하기 10의 마이너스 4승)으로 낮추면 반드시 성능이 좋아질까요?
    -> Learning Rate(학습률)는 모델이 학습하면서 가중치를 한 번에 얼마나 크게 조정할지 결정하는 값입니다. 
    : `2e-4` (0.0002): 상대적으로 큰 폭으로 가중치를 조정합니다.
    : `1e-4` (0.0001): 기존보다 작은 폭으로 가중치를 조정합니다.
    : 즉, `2e-4`에서 `1e-4`로 변경하면 학습률을 절반으로 낮추는 것입니다.
    : 학습률을 낮추면 가중치를 더 작은 폭으로 조정하므로 학습이 안정될 수 있지만, 학습 속도가 느려지거나 충분히 학습하지 못할 수도 있습니다.
    
4. 세 가지 설정을 한꺼번에 변경하지 않고 하나씩 변경하여 비교하는 이유는 무엇인가요?

### Epoch를 늘리면 모델 성능이 좋아질까요?

Epoch를 늘린다고 반드시 모델 성능이 좋아지는 것은 아닙니다. 학습이 부족한 상태라면 성능이 향상될 수 있지만, 너무 많이 학습하면 과적합(Overfitting)이 발생할 수 있습니다.

예를 들어 ResNet18을 3 Epoch에서 10 Epoch로 늘렸을 때 어느 지점에서 성능이 떨어질수도 있습니다. 이는 학습 데이터에 지나치게 맞춰져 새로운 이미지에 대한 일반화 성능이 떨어지는 과적합 현상일 수 있습니다.

### 이번 ResNet18 프로젝트에서는 어떻게 해야 할까요?

현재 `training/finetune.py`의 기본 Epoch는 3입니다. 따라서 3 Epoch에서 아직 Validation Accuracy가 계속 상승하는 추세라면 5, 10 Epoch 등으로 늘려 실험해 볼 가치가 있습니다.

다만 같은 Train·Validation 데이터와 가능한 한 동일한 학습 조건에서 비교해야 합니다.

핵심은 Epoch를 많이 학습하는 것이 아니라, Validation Accuracy가 가장 좋은 시점의 모델을 선택하는 것입니다.

현재 작성된 코드도 매 Epoch마다 Validation Accuracy를 확인하여 가장 높은 정확도를 기록한 모델을 저장하도록 설계되어 있습니다.

> 3 Epoch보다 10 Epoch를 학습했는데 오히려 Validation Accuracy가 떨어졌다면, 어떤 원인을 의심하고 어떻게 개선하겠습니까?

기대 답변: 과적합 가능성을 확인하고 Epoch별 Train Loss와 Validation Accuracy를 비교하겠습니다. 필요하다면 Epoch를 줄이거나 Early Stopping, 데이터 증강, 정규화 등의 방법을 검토하고 성능을 재검증하겠습니다.
